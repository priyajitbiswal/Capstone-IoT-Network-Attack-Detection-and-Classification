Over several development phases, this project accumulated exploratory scripts, eight pre-rendered Jupyter notebooks, multiple experimental variations, historical result summaries, and a conference/journal paper draft. However, an earlier research and dataset audit revealed several fundamental methodological vulnerabilities:
1. **Data Leakage in Legacy Splitting**: Random 80/20 train/test splitting caused ~10.14% flow leakage due to identical feature vectors generated by volumetric flood packets.
2. **Missing Validation Set**: Model selection and hyperparameter exploration were performed directly against test sets.
3. **Flawed XGBoost Class Weighting**: In `src/models.py`, `class_weight='balanced'` was passed to `XGBClassifier`, an argument XGBoost silently ignores, leaving XGBoost completely unweighted against extreme class imbalance.
4. **Throughput Conflation**: Single-core batch array evaluations in RAM were characterized as "10 Gbps line-rate edge wire-speed throughput."
5. **Architectural Divergence**: A corrected, leak-free pipeline (`src_v2/`) was engineered to fix these problems, but baseline retraining (**Stage 3**) has **not** yet been executed.

**Current Operational Rule**: The repository is currently frozen in read-only mode. All original data (`MERGED_CSV/`), sample subsets (`data/`), and legacy models (`models_saved/`) remain intact. No code is modified or deleted, and no model training is underway.

## 4. Comprehensive File-by-File Technical Dictionary

### A. Corrected Pipeline Modules (`src_v2/`)

#### 1. `src_v2/config.py`
- **Purpose**: Central configuration defining directory paths, file pointers, random seeds, class schemas, and feature lists.
- **Inputs**: None (reads environment and relative filesystem paths).
- **Outputs**: Path constants (`RAW_DATA_DIR`, `PARTITIONS_DIR`, `MODELS_V2_DIR`), lists of 39 flow features, class label lists (2, 8, and 34 classes), and label-to-index mapping dictionaries.
- **Interactions**: Imported by all other `src_v2/` modules.

#### 2. `src_v2/data_partitioning.py`
- **Purpose**: Creates deterministic, leak-free 70% Train, 15% Validation, and 15% Internal Test partitions from `data/sample_stratified.csv`.
- **Inputs**: `data/sample_stratified.csv`.
- **Outputs**: `data/partitions/partition_assignments.csv` and `partition_metadata.json`.
- **Internal Mechanics**:
  - Drops 28,464 exact duplicates (identical features AND label).
  - Groups identical 39-dimensional feature vectors together into clusters.
  - Computes an MD5 hash for each unique feature cluster.
  - Hashes the cluster ID with a seed to deterministically assign entire feature clusters to either Train (70%), Val (15%), or Test (15%), ensuring that no identical feature vector can ever appear in more than one partition.

#### 3. `src_v2/cross_capture.py`
- **Purpose**: Extracts an independent, uncontaminated cross-capture evaluation dataset from raw capture files `Merged26.csv` through `Merged40.csv`.
- **Inputs**: Raw CSV files in `MERGED_CSV/` and `data/partitions/partition_assignments.csv`.
- **Outputs**: `data/partitions/cross_capture_test_clean.csv` and `cross_capture_metadata.json`.
- **Internal Mechanics**: Samples flows across all 34 classes from unvisited raw capture files, computes feature hashes, cross-references against the training set, and discards any overlapping feature vectors, yielding 57,280 completely independent cross-capture flows.

#### 4. `src_v2/verify_partitions.py`
- **Purpose**: Four-way set-theoretic verification of zero feature vector overlap between Train, Validation, Internal Test, and Cross-Capture Test sets.
- **Inputs**: Partition assignment CSVs and cross-capture clean CSV.
- **Outputs**: Console audit log and process exit code (0 if zero leakage; 1 if leakage detected).
- **Internal Mechanics**: Hashes all 39 feature values per row into MD5 strings, computes set intersections:
  $$\text{Overlap}(A, B) = |\text{Hashes}(A) \cap \text{Hashes}(B)|$$
  Confirms $\text{Overlap} = 0$ across all 6 partition pairs.

#### 5. `src_v2/ablation_strategy2.py`
- **Purpose**: Generates Strategy 2 ablation partitions where ambiguous feature collisions (identical features assigned to conflicting attack classes) are completely purged.
- **Inputs**: Deduplicated clean rows from `data/partitions/`.
- **Outputs**: `data/partitions/ablation_strategy2/partition_assignments.csv` and `metadata.json`.
- **Internal Mechanics**: Identifies the 8,740 feature vectors that carry multiple conflicting labels (18,416 rows) and purges them completely, leaving 482,682 perfectly separable flows partitioned into 70/15/15.

#### 6. `src_v2/preprocessing.py`
- **Purpose**: Memory-efficient dataset loader, label encoder, and feature normalizer.
- **Inputs**: Partition assignment CSVs and raw sample CSV.
- **Outputs**: Clean, scaled NumPy arrays $(X_\text{train}, y_\text{train})$, $(X_\text{val}, y_\text{val})$, and $(X_\text{test}, y_\text{test})$.
- **Internal Mechanics**: Replaces infinite/NaN values with median, fits `StandardScaler` strictly on $X_\text{train}$, and applies `scaler.transform()` to validation and test sets to prevent distributional leakage.

#### 7. `src_v2/models.py`
- **Purpose**: Model architecture factory providing uniform interfaces for SGD/Logistic Regression, Random Forest, LightGBM, XGBoost, and PyTorch DNN.
- **Inputs**: Model name string, target type (`binary`, `category`, `fine_grained`), hyperparameters.
- **Outputs**: Instantiated classifier object.
- **Internal Mechanics**: Implements `BalancedXGBClassifier` (subclass of `xgb.XGBClassifier`) which computes balanced sample weights via `compute_sample_weight('balanced', y)` inside `fit()`, resolving the silent unweighted flaw of `src/models.py`.

#### 8. `src_v2/evaluate.py`
- **Purpose**: Standardized metric calculation and inference speed profiling.
- **Inputs**: Ground-truth labels $y$, predicted labels $\hat{y}$, predicted probabilities $\hat{P}$, model object, feature matrix.
- **Outputs**: Comprehensive metric dictionary (Accuracy, Macro Precision/Recall/F1, Weighted F1, Log Loss, ROC-AUC, PR-AUC), single-flow latency ($\mu\text{s}$), and batch throughput ($\text{flows/sec}$).

#### 9. `src_v2/run_stage3.py`
- **Purpose**: Master experiment execution runner defining a catalog of 19 sequential baseline experiments.
- **Inputs**: Command-line arguments (`--list`, `--exp <id>`, `--phase <phase>`, `--all`).
- **Outputs**: Centralized experiment ledger (`results_v2/tables/centralized_experiment_ledger.csv`), trained model checkpoints in `models_saved_v2/`, and per-class JSON reports in `results_v2/metrics/per_class/`.
- **Status**: **NOT YET EXECUTED**.

### C. Standalone Research Experiments (`experiments/`)

- `experiments/weight_calibration.py`: Compares unweighted loss, standard inverse balanced weighting ($w_c \propto N / (K \cdot N_c)$), and square-root dampened weighting ($w_c \propto \sqrt{N / (K \cdot N_c)}$). ## 7. The Research Context & Literature Landscape

In `research/`, you have 19 papers from top venues (IEEE TNSM, IEEE IoTJ, Elsevier Computers & Security, etc.) analyzing the CICIoT2023 dataset.

### The Literature Accuracy Paradox
Many published papers claim **98% to 99.5% accuracy** on CICIoT2023 across multi-class tasks. However, our literature audit revealed how this happens:
1. In raw CICIoT2023, **>90% of all packets belong to massive volumetric flood attacks** (`DDoS-ICMP_FLOOD`, `DDoS-UDP_FLOOD`, `DoS-TCP_FLOOD`).
2. Trivial classifiers that predict volumetric floods with 99.9% accuracy achieve an overall accuracy of 99%, even if their recall on stealthy minority attacks (`SQL Injection`, `Command Injection`, `Backdoors`) is **literally 0.0%**.
3. Random train/test splits replicate identical flood packets across splits, artificially rewarding models for memorizing flow coordinates.

### Genuine Research Gaps
1. **True Minority Defense under Zero Leakage**: How do machine learning models actually perform when identical flow coordinates are prevented from leaking into the test set?
2. **Ambiguity Deconstruction**: Quantifying how much classification failure is caused by stripped packet headers (e.g., distinguishing DoS from DDoS without source IP addresses) versus classifier weakness.
3. **Generalization Across Captures**: Most published papers evaluate on a single capture. Evaluating on independent capture days (`cross_capture_test_clean.csv`) tests whether models memorize static network artifacts.
4. **Realistic Deployment Constraints**: Measuring latency and memory on CPU hardware with realistic packet batching, rather than claiming unrealistic wire-speed saturation.
